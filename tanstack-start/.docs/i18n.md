# Internationalization

The frontend uses Intlayer with `ru` and `en`; Russian is the default. Locale is
stored only in `APP_LOCALE`. URLs, search params and auth redirects have no
language prefix, and `Accept-Language` does not override the cookie/default.

## Cookie and SSR

`shared/lib/i18n/locale.ts` defines the allowed locales and cookie contract:
`Path=/`, `SameSite=Lax`, one-year max age, no `HttpOnly`, and `Secure` in
production or on HTTPS. It is a UI preference, not an authentication cookie.
Invalid and missing values resolve to `ru`.

`getRequestLocale` reads the incoming cookie through a server-only Start boundary.
`getRouter()` resolves it separately for each request and passes it in router
context. Custom `dehydrate`/`hydrate` callbacks preserve the server locale for the
first client render; the Query integration wraps these callbacks. Never put the
current locale in mutable module-global state on the server.

`RootDocument` owns locale state, `html lang/dir` and `IntlayerProvider`. Call
`useAppLocale().setLocale('en')` to update both the cookie and live UI. For external
cookie management, the exported `persistLocale` helper writes the same contract;
a direct cookie edit is picked up by a reload. Intlayer's automatic storage and
routing proxy are disabled to avoid a second cookie or language redirects.

Locale changes must not invalidate the router or Query cache. `LocalizedTitle`
reads each matched route's `staticData.titleKey` and renders a React 19 `<title>`
reactively, including SSR. Route adapters own their title key. Translation changes
must not rerun auth guards, reload data or reset an unsaved form.

## Dictionaries

Put `*.content.ts` next to its owning page, widget, feature or shared component.
Use a unique dictionary key, `t({ ru: ..., en: ... })`, and `satisfies Dictionary`.
Use `useIntlayer('key')` inside React. For string props such as `aria-label`,
placeholder and toast messages, read `.value`. Use Intlayer `insert` for parameters.
Outside React, call `getIntlayer('key', locale)` with an explicit request locale.
Do not put dictionaries in `routes/` or edit `.intlayer/` output by hand.

Build Zod schema messages from the current locale, not module-scope translated
strings. Use `createRequiredString(locale)` / `createFileSchema(locale)` from
`shared/lib/schemas` when using those shared primitives. The legacy constants
retain Russian defaults for compatibility.

`getMessageFromError(error, fallback, locale)` translates known file-error codes
and generic fallback messages. Arbitrary backend messages remain as returned by
the server; never translate user content or raw exception text heuristically.

Pass the current locale as the fourth argument of `formatDate`. Calendar defaults
to the selected language; explicit calendar locale props still take precedence.

## Generation and verification

Use Bun only. `bun run dev` / `build` generate dictionaries through the Vite plugin.
`bun run typecheck` regenerates dictionary types before running TypeScript.
`bun run check` includes `i18n:check`, which regenerates dictionaries and checks
missing translations. Generated `.intlayer/` output is ignored by Git and linters.
Vitest uses the Intlayer plugin and inlines its packages so runtime aliases also
apply inside jsdom.

For locale changes verify cookie parsing, SSR HTML and title, hydration with a
cookie changed after the request, switching in both directions, persistence after
reload and absence of router invalidation. Full SSR checks may use an isolated
mock auth API. Production builds require `VITE_API_BASE_URL` at build time and
`SERVER_URL` / optional `SERVER_API_BASE_URL` at runtime.
